## 0. 🔒 인증키 취급 원칙 (반드시 읽을 것)

> ### ⚠️ 이 문서에 인증키를 적지 마십시오.
>
> 이 파일은 git 저장소에 올라갑니다. 키를 적으면 **저장소에 접근 가능한 모든 사람에게 노출**되며, 한 번 커밋된 키는 나중에 지워도 이력에 남습니다.

| # | 규칙 |
|---|---|
| K-1 | 인증키는 **저장소 최상단**의 `.env` 파일에만 둔다 |
| K-2 | `.gitignore`에 `.env`를 반드시 추가한다 (커밋 전 확인) |
| K-3 | 코드에서는 `common/config.py`를 통해서만 키를 읽는다. 커넥터에 직접 문자열로 넣지 않는다 |
| K-4 | 키는 **개인 계정에 귀속**된다. 팀원 각자 발급받아 각자의 `.env`에 넣는다 |
| K-5 | 이 문서에는 **"누가 발급받았는지"만** 기록한다 |

### data.go.kr 키는 계정당 1개다

**승인받은 8건은 모두 같은 인증키 하나로 호출된다.** 활용신청은 "이 키로 저 API도 열어달라"는 권한 추가일 뿐이므로, `.env`에 들어가는 data.go.kr 키는 **한 줄이면 충분하다.**

**`.env`** (커밋되지 않음)

```
# 공공데이터포털 승인 8건 공통 키 — 목록은 docs/10-data-sources.md 참고
DATA_GO_KR_SERVICE_KEY=본인_디코딩키

# 별도 포털 (미발급 시 빈칸)
ECOS_API_KEY=
OPINET_API_KEY=
```

**`.env.example`** (커밋함 — 키 없이 이름만)

```
DATA_GO_KR_SERVICE_KEY=
ECOS_API_KEY=
OPINET_API_KEY=
```

> 파이썬 `requests`의 `params=`로 넘길 때는 **디코딩키**, URL에 직접 붙여 쓸 때는 **인코딩키**를 쓴다.

### S-7. 금융위원회_기업 재무정보 🟡

| 항목 | 값 |
|---|---|
| 커넥터 | `backend/batch/connectors/fsc_connector.py` |
| 환경변수 | `DATA_GO_KR_SERVICE_KEY` |

**⚠️ 커버리지가 이 API의 핵심 쟁점이다.**

금융공공데이터 개방 사업의 기업 재무정보는 일반적으로 **상장법인·외부감사대상법인** 범위다. 이 범위가 맞다면 다음이 성립한다:

| | 대상 |
|---|---|
| 포함 | 상장사, 외감법인 — **전국 수만 개 수준** |
| 제외 | 지점 상권의 절대다수인 소상공인·비외감 중소법인 |

즉 **접촉 명부의 주력 신호가 될 수 없다.** 국민연금 데이터가 59만 개 사업장을 커버하는 것과 대비된다.

**쓸 수 있는 용도**
- 명부에 오른 기업 중 **외감법인인 경우에만** 브리프에 재무 맥락을 덧붙이는 보강 정보
- RM이 방문 전 참고할 "이 회사 매출 규모" 수준

**착수 전 확인**
- [ ] 실제 수록 기업 범위 (상장/외감/전체)
- [ ] 조회 키가 사업자등록번호인지 법인등록번호인지 종목코드인지 ← **연계 가능성을 좌우**
- [ ] 제공 항목 (총자산·매출액·당기순이익 등)

> 벤치마킹한 기존 CRM의 기업고객 싱글뷰에는 이미 내부 재무정보가 풍부하다. **우리가 이 영역에서 내부 시스템을 이길 수 없다.** 차별점은 "아직 고객이 아닌 사업체"이므로, 여기에 자원을 많이 쓰지 말 것.

> - **S-1 상가(상권)정보의 사업자번호 제공 여부가 이 API의 실효성을 결정한다** → S-1 착수 전 확인 항목

|---|---|---|

| 1차 | 국민연금 **가입상태코드**(2=탈퇴) | 법인 모집단 |
| 2차(보완) | **국세청 조회** | 사업자번호가 확보된 건에 한해 |

**MVP 목표인 "명부 내 휴폐업 0건"은 1차 배제만으로 달성 가능하다.**

## 4. ⚠️ 착수 전 결정 — 지방행정 인허가 변동분 API

**승인 8건에 지방행정 인허가가 없다.** 이것이 현재 가장 중요한 공백이다.

| 신호 | 소스 | 주기 | 확보 여부 |
|---|---|---|---|
| 사업체 모집단 | S-1 상가(상권)정보 | 분기 | ✅ 승인됨 |
| 법인 모집단 + 인력 증감 | F-1 국민연금 | 월 | ✅ 파일 |
| **신규 개업 / 폐업** | **지방행정 인허가 변동분** | **일** | ❌ **미신청** |
| 상권 신호 | S-2 기상특보 | 수시 | ✅ 승인됨 |
| 명절·공휴일 | S-3 특일정보 | 연 | ✅ 승인됨 |

**왜 문제인가**

`CHANGE-REQUEST_v1.2.0.md` CHG-04에서 지적한 "매일 같은 20건이 뜨는 문제"의 해법은 **사업체 단위로 시간에 따라 변하는 신호**를 확보하는 것이었다. 현재 확보된 것은:

- 국민연금 인력 증감 → **월 단위**
- 상가정보 점포 증감 → **분기 단위**

**일 단위로 변하는 사업체 신호가 하나도 없다.** 07:30 일간 배치를 돌려도 어제와 오늘의 명부가 같아진다.

**판단**

| 선택지 | 평가 |
|---|---|
| **A. 인허가 변동분 API 추가 신청** | 🔴 권장. 자동승인 가능성이 높고 비용 0 |
| B. 일간 배치를 주간 배치로 변경 | 🟡 차선. "매일 아침 브리프"라는 제품 컨셉이 무너짐 |
| C. 그대로 진행 | ❌ 심사에서 "매일 같은 명부 아닌가" 질문에 답할 수 없음 |

→ **A를 이번 주 안에 처리할 것.**
