# CRM 연동 정리 (REQ-07)

- **버전**: v1.1.0
- **최종 수정**: 2026-10-14
- **관련 요구사항**: REQ-07 CRM 등록 파일 생성
- **관련 유스케이스**: UC-08 CRM 등록 파일 다운로드
- **단계**: MVP

---

## 1. 개요

C-MAKER는 CRM과 **단방향 파일 기반**으로 연동한다.

RM이 접촉 명부(TOP 20)에서 접촉한 사업장을 '방문함'으로 태깅하면, 시스템이 그 건들을 사내 CRM 고객관리 등록 항목 순서에 맞춘 CSV/XLSX 파일로 생성한다. RM은 이 파일 내용을 기존 CRM에 등록한다. 양방향 실시간 API 연동은 Phase 3 이후 재검토한다.

```
C-MAKER                                   CRM
─────────────                             ─────────
접촉 명부 생성 → RM '방문함' 태깅
  → CRM 등록 파일 다운로드 (CSV/XLSX)  →  RM이 CRM에 등록
```

> CRM의 일괄 업로드 기능 지원 여부는 확인 전이다. 그래서 이 파일을 '업로드 파일'이 아니라 **'등록 파일'** 로 부른다(`backend/api/services/recommendation_service.py` 주석).

---

## 2. 범위

### MVP 범위 (현재)
- '방문함' 태깅 건 → CRM 등록용 파일(CSV/XLSX) 생성 및 다운로드
- 사내 CRM [02220] 고객관리 등록 항목 순서에 맞춘 컬럼 구성

### Out of Scope
- CRM 양방향 실시간 API 연동 — Phase 3 이후 재검토
- CRM에서 태깅 결과를 역으로 받아오는 피드백 루프
- 실제 문자·알림톡 발송 — 초안 생성까지만, 발송은 기존 채널 담당

## 3. 파일 스펙

근거 코드: `backend/api/services/recommendation_service.py`(`CRM_COLUMNS`, `build_export`), `backend/api/repositories/recommendation_repository.py`(`export_rows`), `backend/config/pipeline.toml`(`[product_mapping.*]`).

### 대상 행
- 요청 일자 명부 중 **'방문함'(VISITED)으로 태깅한 건**이면서 **영업상태 '정상'** 인 건만 담는다. 보류·부적합·미태깅 건은 포함하지 않는다.
- 행 순서는 명부 순위순이다.

### 형식

| 항목 | 값 |
|------|------|
| 포맷 | CSV 또는 XLSX 중 선택 |
| CSV 인코딩 | UTF-8 BOM(`utf-8-sig`) — Excel에서 한글이 깨지지 않도록 |
| XLSX 시트명 | `접촉명부` |
| 파일명 | `cmaker_{지점코드}_{YYYY-MM-DD}.{csv\|xlsx}` |
| 수식 주입 방지 | 값이 `=`, `+`, `-`, `@`, 탭, CR로 시작하면 앞에 `'`를 붙인다(CSV injection 방지) |
| 전화번호 | **열을 두지 않는다** — 두낫콜(수신거부) 확인이 선행되어야 한다 |

### 컬럼 구성 (사내 CRM [02220] 고객관리 등록 항목 순서, 10개)

| # | 컬럼 | 값 | 비고 |
|---|------|------|------|
| 1 | 사업자등록번호 | 공란 | 사업자번호 미확보 — 공란으로 둔다 |
| 2 | 상호명 | 사업체 상호 | |
| 3 | 상담일자 | '방문함' 태깅일 (KST 날짜, `YYYY-MM-DD`) | `tagged_at`의 Asia/Seoul 날짜 |
| 4 | 고객관리유형 | `상품추진` | 고정값 |
| 5 | 상세유형 | 대표 신호의 `product_mapping.detail_type` | 아래 매핑표. 대표 신호가 없으면 공란 |
| 6 | 채널 | `방문` | 고정값 |
| 7 | 유입경로 | `신규(가망)고객` | 고정값 |
| 8 | 추진상품 | 대표 신호의 `product_mapping.crm_products` (쉼표로 연결) | 아래 매핑표. 대표 신호가 없으면 공란 |
| 9 | 내용 | `[NH Campaigner] ` + 선정 사유 1줄 + ` [출처 태그]` | 최대 1000자에서 자른다. 출처 태그는 첫 번째 사실 문장의 태그 |
| 10 | 등록사무소코드 | 지점코드 | |

대표 신호는 그 추천의 기여도 1위 신호다(브리프 '추천상품' 줄과 같은 기준).

### 대표 신호 → 상세유형·추진상품 매핑 (`pipeline.toml [product_mapping]`)

브리프 '추천상품' 줄과 CRM 등록 파일이 이 표 하나를 쓴다. 규칙으로 붙이는 표시 정보이며 AI 화법에는 넣지 않는다.

| 대표 신호 | 상세유형 (`detail_type`) | 추진상품 (`crm_products`) | 브리프 추천상품 (`brief_products`) |
|------|------|------|------|
| `NEW_BUSINESS_OPENING` 신규 개업(사업체) | 수신추진 | 수신, 전자금융, 카드 | 사업잘되는NH통장, 기업인터넷뱅킹, 기업스마트뱅킹, All My Biz카드 |
| `INDUSTRY_NEW_OPENINGS` 신규 개업(동일 업종) | 여신추진 | 여신 | NH온택트보증서대출 |
| `AREA_NEW_OPENINGS` 신규 개업(상권) | 여신추진 | 여신 | NH온택트보증서대출 |
| `FX_DAILY_CHANGE` 환율 일변동 | 외환추진 | 외환 | NH외환서비스 |
| `OIL_PRICE_CHANGE` 유가 일변동 | 여신추진 | 여신, 카드 | NH온택트보증서대출, All My Biz카드 |
| `WEATHER_WARNING` 기상특보 | 여신추진 | 여신 | NH온택트보증서대출 |
| `TEMP_SHIFT_FORECAST` 기온 급변 예보 | 여신추진 | 여신 | NH온택트보증서대출 |
| `SEASON_SHIFT_FORECAST` 계절 전환 예보 | 여신추진 | 여신 | NH온택트보증서대출 |
| `FIRST_FREEZE_FORECAST` 첫 영하 예보 | 여신추진 | 여신 | NH온택트보증서대출 |
| `FIRST_HEAT_FORECAST` 첫 폭염 예보 | 여신추진 | 여신 | NH온택트보증서대출 |

### 인수 기준 (UC-08)
- 다운로드한 파일을 CRM에 등록할 때 **수작업 편집이 필요 없어야** 한다

## 4. 연동 흐름

```
1. 매일 07:30 배치 완료
       ↓
2. RM이 대시보드에서 접촉 TOP 20 확인
       ↓
3. 접촉한 사업장을 '방문함'으로 태깅
       ↓
4. "CRM 등록 파일 다운로드" 클릭 (화면 버튼: "CRM 등록 파일 받기" → CSV / Excel(XLSX) 선택)
       ↓
5. '방문함' + 영업상태 정상 건으로 CSV / XLSX 파일 생성 및 다운로드
       ↓
6. RM이 파일 내용을 기존 CRM에 등록
```

---

## 5. API 엔드포인트

FastAPI 기반으로 아래 엔드포인트를 제공한다(`backend/api/routers/recommendations_router.py`).

```
GET /api/recommendations/export
  ?date=YYYY-MM-DD      # 생략 시 오늘(KST)
  &format=csv|xlsx      # 생략 시 csv
```

- **권한**: RM 전용. 지점은 경로 파라미터가 아니라 **로그인 토큰의 소속 지점**으로 결정한다.
- **응답**: 파일 다운로드 (Content-Disposition: attachment, 파일명 §3)

---

## 7. Phase 3 고도화 방향

현재는 파일 기반 단방향 연동이지만, Phase 3에서 아래를 검토한다.

- CRM API 직접 연동 (Push 방식)
- 태깅 결과를 CRM에서 역으로 수신 (양방향)
- CRM 내 접촉 이력과 C-MAKER 채택률 연계
