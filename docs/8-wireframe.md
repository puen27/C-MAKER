## 0. 문서 목적 및 전제

본 문서는 `4-project-principle.md`(v1.5.0) 6장에 정의된 프론트엔드 페이지(`frontend/src/pages/`)의 화면 구조를 정의한다. 시각 스타일(컬러·타이포그래피·컴포넌트 톤)은 `9-style-guide.md`에서 다루며, 본 문서는 레이아웃과 정보 배치만 다룬다.

- `2-prd.md`(v1.4.0) 6장에 따라 **데스크톱 우선**(1280px 기준)으로 설계하고, 태블릿(768~1279px)까지 대응한다. 모바일 전용 레이아웃은 이 단계에서 정의하지 않는다(영업점 창구·사무 공간에서 데스크톱/태블릿으로 사용하는 것을 전제로 한다).
- 화면 접근 권한은 역할(RM/지점장/본부(마케팅)/본부(준법))에 따라 다르다(VAL-08). 아래 각 화면에 접근 가능한 역할을 명시한다.
- Phase 2·3 전용 화면(운영 브리핑, 캠페인, 채택률 대시보드)도 함께 정의하되, 실제 구현 시점은 `7-execution-plan.md`를 따른다. (v1.4.0) 현재 프론트엔드에는 이 화면들의 라우트·메뉴가 없다 — 각 절에 **미구현(Phase 2/3)** 으로 표기한다.
- (v1.1.0) 2026-09-08 제공된 NH뱅크 인터넷뱅킹 화면 캡처를 레이아웃 참고 자료로 반영한다: 최상단 유틸리티 바(사용자/세션/보조 링크) 분리, 상태 전환용 밑줄 탭, 카드 내 액션 버튼 가로 배치, 항목 앞 outline 배지. 스타일(색상·형태) 세부는 `9-style-guide.md` §5.7~5.8을 따른다. (v1.1.2) 참고 캡처의 "큰글" 접근성 토글은 C-MAKER 요구사항(REQ/UC)에 근거가 없어 반영하지 않는다.
- (v1.4.0) 화면 표시 서비스명은 **NH Campaigner**다(C-MAKER는 시스템·코드명, `index.html` `<title>`도 NH Campaigner). 루트 `NH-Campaigner-UI-proposal.html`의 P0/P1 제안(아침 브리핑, 데이터 기준 도장, 오늘 기록 패널, 신호별 대상 막대, 한 줄 명부 행, 브리프 근거·화법 분리 등)이 구현에 반영되어 있으며, 아래 목업은 그 구현 기준이다. 목업 안의 상호·수치·문구 일부는 설명용 예시다.

## 1. 공통 레이아웃

모든 인증 화면은 **상단 유틸리티 바 + 좌측 고정 사이드바 + 지점 헤더 + 콘텐츠 영역** 구조를 공유한다. 사이드바 메뉴는 역할에 따라 달라진다.

```
┌────────────────────────────────────────────────────────────────────┐ ← 상단 3px 주색(Human Blue) 선
│ [NH Campaigner 시그니처] │ 영업점 아웃바운드 캠페인 에이전트                │
│                              한서영 지점장 · 24:13 · 연장 · 로그아웃 │
├───────────────┬──────────────────────────────────────────────────┤
│               │ 지점명 강남중앙지점                    한서영 (지점장) │
│ ▣ 오늘의 접촉  ├──────────────────────────────────────────────────┤
│               │ ⚠ 일부 신호가 지연되었습니다(기준일 1일 전)           │  ← 대시보드 외 화면의 지연 배너
│               │   (기상청 1일 전)                    [ 수동 재연동 ]│  ← 지점장/본부(마케팅)만 버튼 렌더링
│               ├──────────────────────────────────────────────────┤
│               │                     콘텐츠 영역                     │
│               │                  (최대 폭 1120px)                   │
└───────────────┴──────────────────────────────────────────────────┘
```

- 최상단 유틸리티 바(`TopUtilityBar`, `9-style-guide.md` §5.8)는 화면 전환과 무관하게 항상 고정 노출된다.
  - 좌측: NH Campaigner 공식 시그니처(심볼+워드마크 이미지 `public/brand/nh-campaigner.svg`, `BrandSignature`) | 세로 구분선 | 부제 "영업점 아웃바운드 캠페인 에이전트". 1279px 이하에서는 구분선·부제를 숨긴다. 시그니처에 워드마크가 들어 있으므로 옆에 서비스명을 글자로 다시 쓰지 않는다.
  - 우측: **사용자명** + 역할 라벨 · 세션 남은 시간(카운트다운) · 연장(세션 연장 가능 계정만) · 로그아웃. 남은 시간이 5분 이하가 되면 타이머가 경고색 + `⏱`로 바뀌고, 0이 되면 자동 로그아웃 후 로그인 화면으로 이동한다.
  - (v1.4.0) 기존 목업의 "고객센터 · 도움말" 보조 링크 줄은 구현되지 않아 삭제했다.
- 그 아래는 좌측 사이드바 + [지점 헤더 + 콘텐츠 영역] 구조다. 지점 헤더 좌측은 "지점명 {지점명}"(지점 소속이 없는 본부 계정은 "본부"), 우측은 사용자명 + 역할 outline 배지다(드롭다운 없음).
- 사이드바 메뉴는 20px 아이콘 + 라벨이며, 1279px 이하에서는 64px 아이콘 전용 모드가 된다. `/brief/:id` 화면에서도 "오늘의 접촉" 메뉴가 활성으로 표시된다.

| 역할 | 현재 노출 메뉴(MVP, `utils/roles.ts`) | 로그인 후 첫 화면 | 미구현 메뉴(Phase 2·3 구현 시 추가 예정) |
|---|---|---|---|
| RM | 오늘의 접촉 | `/dashboard` | — |
| 지점장 | 오늘의 접촉 | `/dashboard` | 운영 브리핑(Phase 2), 캠페인(Phase 3) |
| 본부(마케팅) | 임계치 관리 | `/admin/thresholds` | 채택률 대시보드(Phase 2) |
| 본부(준법) | (메뉴 없음) | `/pending` 안내 화면 | 캠페인 승인 대기열(Phase 3) |

- 미구현 메뉴는 비활성 표시도 하지 않고 DOM에 렌더링하지 않는다(`9-style-guide.md` §5.6). 본부(준법) 계정은 사이드바가 비어 있고, 첫 화면 `/pending`(`PendingPage`)에 "본부(준법) 역할의 캠페인 승인 화면은 Phase 3에서 제공됩니다. 현재 단계(MVP)에서 이용할 수 있는 메뉴가 없습니다." 안내만 표시한다.
- 데이터 지연 안내(RULE-SENSE-04)는 화면에 따라 두 가지로 나타난다.
  - 오늘의 접촉 화면: 상단 배너 대신 아침 브리핑 아래 **데이터 기준 도장**(`DataFreshnessStamps`, §3)과 그 아래 한 줄 안내로 표시한다.
  - 그 외 화면(브리프 상세, 임계치 관리 등): 콘텐츠 영역 맨 위 경고 배너(`DataDelayBanner`)로 "⚠ {서버 안내 문구}"와 대체 데이터를 쓴 소스별 지연일("(기상청 1일 전)" 형식)을 표시한다.
  - 안내 문구는 서버가 상황별로 내려준다: "일부 신호가 지연되었습니다(기준일 N일 전).", "일부 데이터를 수집하지 못했습니다: {소스}.", "오늘 일간 배치가 실패했습니다. 일부 데이터가 최신이 아닐 수 있습니다.", "오늘 추천 명부가 생성되지 않았습니다.", "오늘 일간 배치가 아직 완료되지 않았습니다." 등. 지연이 없으면 배너·안내 줄 모두 나타나지 않는다.
- 안내 우측의 **[ 수동 재연동 ]** 버튼(`ManualBatchTrigger`, REQ-17·UC-18)은 지점장·본부(마케팅) 역할에만 렌더링된다(RM·본부(준법)에는 안내만 보이고 버튼은 DOM에 없음).
- 버튼 클릭 시 확인 다이얼로그(제목 "수동 재연동", "일간 배치를 지금 다시 실행할까요? 완료까지 수 분이 걸릴 수 있습니다.", [실행]) → 확인 시 요청 전송. 실행 중에는 버튼이 "재연동 중…"으로 비활성화되고 옆에 "예상 완료 {일시}"를 보여준다. 이미 실행 중인 배치가 있으면 "이미 실행 중인 배치가 있어 새로 실행하지 않았습니다."를 표시한다. 완료되면 "재연동이 완료되었습니다. …" 또는 "재연동이 실패했습니다: {사유}" 안내([닫기] 포함)를 띄우고 추천·브리프 데이터를 다시 불러온다(UC-18 인수 기준).
- 쿨다운(VAL-12, 기본 30분) 중에는 버튼이 비활성화되고 버튼 옆 보조 텍스트와 툴팁으로 "N분 후 다시 시도할 수 있습니다"를 보여준다.

- **아침 브리핑**(좌): 날짜("10월 14일 수요일") → 헤드라인 "오늘 만날 N곳을 선정했습니다"(명부가 비어 있으면 "오늘의 접촉") → 둘째 줄 "{신호명} N곳이 먼저입니다."(1순위 추천의 대표 신호와 그 신호의 건수. 신호 묶음이 하나뿐이거나 맨 앞 묶음이 '기본 조건'이면 생략) → 절사된 이벤트가 있을 때만 "오늘 감지된 이벤트 N건 외 M건"(RULE-SENSE-02).
- **데이터 기준 도장**(`DataFreshnessStamps`): "데이터 기준" 라벨 뒤에 출처별 `[▤ 출처명 MM.DD]` 도장을 나열한다. 소스 장애로 이전 데이터를 쓴 출처에만 "지연" 라벨을 붙이고, 오늘 수집하지 못한 출처는 날짜 자리에 "미수집"을 쓴다. 공표 주기 때문에 기준일이 며칠 전인 것은 지연이 아니다. 도장 툴팁·스크린리더 문구로 "{출처} 기준일 YYYY-MM-DD(. 소스 장애로 이전 데이터를 사용했습니다.)"를 제공한다. 서버 안내 문구(§1)가 있으면 도장 아래 한 줄로 보여주고, 지점장에게는 그 줄에 [ 수동 재연동 ] 버튼을 둔다(UC-18).
- **오늘 기록**(`TodayRecordPanel`, 가운데): "기록한 수/ 전체 곳" 큰 숫자, 방문함·보류·부적합 비율 막대, 범례 4칸(방문함·보류·부적합·기록 전 건수). 어제 명부에 기록하지 않은 곳이 있으면 "● 어제 기록하지 않은 곳 N곳"을 붙인다(UC-09 예외 흐름). 하단 고정 문구 "기록은 내일 명부에 반영됩니다." 오늘 명부의 처리 현황일 뿐 개인 성과 지표가 아니므로 비율(%)·달성률로 표기하지 않는다(CLAUDE.md §0.7).
- **신호별 대상**(`SignalBarsPanel`, 우): 오늘 명부를 대표 신호(추천의 `signalType`)별로 묶어 "신호명 · 막대 · 건수"로 보여준다. 순위가 높은 추천의 신호가 위에 온다. 신호명은 `utils/signal.ts` 기준(신규 개업, 같은 업종 개업, 주변 상권 개업, 환율 변동, 유가 변동, 기상특보, 기온 급변 예보, 계절 전환 예보, 첫 영하 예보, 첫 폭염 예보)이며, 기여 신호 없이 선정된 추천은 "기본 조건", 매핑에 없는 신호는 "기타 신호"로 묶는다. 막대를 누르면 그 신호의 사업장만 명부에 보이고(아래 "~만 보는 중" 칩), 같은 막대를 다시 누르면 해제된다.
- 명부가 비어 있으면 오늘 기록·신호별 대상 패널을 그리지 않는다.
- 1279px 이하에서는 아침 브리핑이 한 줄을 차지하고 두 패널이 그 아래 2열로, 767px 이하에서는 1열로 쌓인다.

**(b) 안내 배너(조건부) + 명부 시트 + 하단**

- **안내 배너**(정보 톤, 조건부): 상권 공통 사유만으로 선정된 비율이 기준(`AREA_REASON_RATIO_LIMIT`)을 넘으면 "오늘 명부의 N%가 상권 공통 사유만으로 선정되었습니다(기준 M% 초과)."(RULE-TARGET-06). 오늘 명부가 비어 있는데 어제 미기록 건이 있으면 오늘 기록 패널 대신 "어제 명부에서 기록하지 않은 곳이 N곳 있습니다." 배너를 보여준다.
- **기록 상태 탭**: `전체 / 기록 전 / 방문함 / 보류 / 부적합` 밑줄 탭(`9-style-guide.md` §5.7)에 상태별 건수를 붙인다(명부가 비어 있으면 건수 생략). 탭 건수는 신호 필터와 무관하게 오늘 명부 전체 기준이다. 탭과 신호 필터는 함께(AND) 적용되며, 목록 순서(순위)는 바꾸지 않고 보기만 거른다 — 필터가 배제·재정렬 로직에 관여하지 않는다.
- **도구 영역**(탭 오른쪽): 신호 필터가 걸려 있으면 "{신호명}만 보는 중 ×" 칩(× = 필터 해제). RM에게만 **[ CRM 등록 파일 받기 ▾ ]** 버튼(Primary 사각)이 렌더링되며, 누르면 `CSV` / `Excel (XLSX)` 형식 메뉴가 열린다. 생성 중에는 "파일 생성 중…"으로 비활성화되고, 명부가 비어 있으면 비활성이다. 파일에는 오늘 명부 중 **'방문함'으로 기록하고 영업상태가 '정상'인 건만** 담긴다(UC-08, 서버 `export_rows`).
- **한 줄 명부 행**(`RecommendationCard`): `순위 숫자 | 상호명(굵게)·업종 | 선정 사유 1줄 + 출처 도장 | 기록 버튼` 4열 그리드다.
  - 업종은 원본 분류의 마지막 단계만 보여주고(`industryLeaf`, 예: '시설관리·임대·여행사·보조·여행사' → '여행사'), 전체 분류는 툴팁으로 제공한다. 업종은 배지가 아닌 상호명 아래 보조 글자다.
  - 선정 사유는 배치가 만든 요약 1줄이며 넘치면 말줄임(전체는 툴팁), 그 아래 대표 출처 도장 `[▤ 출처명 MM.DD]`를 붙인다.
  - **점수는 표시하지 않고 순위 숫자만** 둔다. 탐색 슬롯 여부(RULE-TARGET-04)와 행별 '어제 미기록' 배지도 표시하지 않는다(어제 미기록은 오늘 기록 패널의 수로만).
  - 행 왼쪽 3px 막대가 기록 상태를 나타낸다(방문함 그린·보류 옐로우·부적합 회색, 기록 전은 막대 없음). 부적합 행은 상호명·사유를 흐리게 표시한다.
  - 행을 클릭하거나 상호명 링크를 누르면 `BriefDetailPage`(4장)로 이동한다(키보드·보조기기는 상호명 링크로 이동). 기록 버튼 영역 클릭은 이동하지 않는다.
  - 1279px 이하에서는 사유가 상호명 아래로, 기록 버튼은 다음 줄로 내려간다.
- **기록 버튼**(`TagButtons`, RM만): `[방문함] [보류] [부적합 ▾]`. 클릭 1회로 저장하고(페이지 이동 없음, UC-09), 현재 상태 버튼은 상태색 채움 + `✓`로 표시한다. 같은 상태를 다시 누르면 아무 일도 하지 않는다. '부적합 ▾'는 "부적합 사유" 메뉴(이미 거래중 / 대상 아님 / 정보 오류 / 접촉 불가, VAL-06)를 열며 사유를 고르면 저장된다. 부적합으로 저장된 버튼은 "부적합 · {사유}"로 표시한다. 지점장에게는 버튼 대신 읽기 전용 상태 배지(기록 전 / 방문함 / 보류 / 부적합 · {사유})를 보여준다.
- **되돌리기 토스트**(`TagUndoToast`): 기록 직후 화면 하단 가운데에 "{상호명} · {상태} 저장됨 [되돌리기] ×"를 10초간 띄운다(UC-09 인수 기준 "저장 직후 되돌리기"). 저장 실패 시 같은 자리에 오류 문구를 띄운다.
- **빈 상태**: 명부 미생성 시 "오늘의 접촉 명부가 아직 생성되지 않았습니다. 일간 배치 완료 후 표시됩니다.", 필터 결과가 없으면 "이 조건에 맞는 사업장이 없습니다."
- **투명성 문구**(하단 고정): "대상과 사유는 공공데이터를 기준으로 규칙이 정하고, 전화 화법은 AI가 작성합니다. 고객 개인정보는 다루지 않습니다."

- **날씨 참고**(있을 때만): 선정 사유와 분리된 별도 카드. "선정 사유가 아닌 참고 정보입니다. 방문 일정을 정할 때 참고하세요."
- **방문 전 확인**(체크리스트가 있을 때만): 체크박스 2열(1279px 이하 1열). 체크 상태는 화면 표시만 하고 저장하지 않는다.
- **전화 화법**: 제목 옆에 생성 방식 배지 — "AI 작성"(LLM) 또는 "기본 화법"(템플릿, 이때 안내 "문장 생성 서비스가 연결되지 않아 기본 화법을 보여줍니다."). 화법은 ① 인사·연락 사유 ② 연락 목적(사장님 입장에서 지점이 도울 일) ③ 방문·상담 요청의 3문장 구조이고, 3문장이 모두 있을 때만 단계명 `인사 / 용건 / 약속`을 붙인다(일부가 검증에서 빠지면 1·2… 번호). [화법 복사]로 클립보드에 복사한다. 연락 사유·목적은 가장 기여도 높은 신호로 정한다.
- 근거 없는 문장은 이미 생성 단계에서 제거되어 이 화면에 나타나지 않는다(RULE-BRIEF-02). 화법이 모두 차단된 경우 "근거가 확인되지 않은 문장이 검증 단계에서 차단되어 선정 사유만 표시합니다."를 보여준다.
- **통화 안내(고정 문구)**: AI 화법과 별개로 규칙이 붙이는 안내다. "통화 시작 전"에는 로그인 직원의 지점명·이름을 넣은 고지 항목, "통화 마칠 때"에는 연락 거부 안내 문장을 보여준다(문구 확정 전 준법감시 확인 필요 — 코드 주석).
- **접촉 결과**: `DashboardPage`와 같은 기록 버튼(`TagButtons`, RM만, 지점장은 읽기 전용 배지)과 "기록은 내일 명부에 반영됩니다.", 연락 거부 고객 처리·방문 시간 안내 문구. 기록 후 §3과 같은 되돌리기 토스트가 뜬다.
- 하단에 §3과 같은 투명성 문구를 둔다.

- 화면은 임계치 항목을 `category`로 나눈 두 표다: **신호 승격 임계치**(`SIGNAL`)와 **운영 파라미터**(`SYSTEM`). 표 제목 옆에 항목 수를 붙인다. 항목명·설명·단위는 서버 값(`threshold_config.label/description/unit`)을 그대로 보여준다(위 항목명은 초기 데이터 기준).
- 표는 `항목(이름 + 설명) | 현재 임계치 | 최근 수정(일시 + 수정자, 수정 이력이 없으면 "초기값") | 변경 이력 ▾` 4열이다.
- **고정값 항목**(`is_fixed`, 예: 신규 개업(사업체)·기상특보·첫 영하 예보·첫 폭염 예보)은 입력창·저장 버튼 없이 점선 배지 "발효 즉시 (고정)"만 보여주며 편집할 수 없다. 변경 이력 조회는 가능하다.
- 편집 가능한 항목은 숫자 입력(우측 정렬) + 단위 + [저장](Primary 사각). 값이 바뀌었을 때만 저장 버튼이 활성화되고, 요청 중에는 "저장 중…"이다.
- 저장 시 즉시 검증(VAL-05)한다 — "값을 입력해주세요." / "숫자를 입력해주세요." / "0 이상이어야 합니다." / "정수만 입력할 수 있습니다."(정수 전용 항목) / "최소 N{단위}" / "최대 N{단위}". 오류는 입력창 아래에 표시하고, 서버도 같은 규칙으로 다시 검증한다. 성공 시 "저장되었습니다. 다음 배치부터 적용됩니다."
- [변경 이력 ▾]를 누르면 해당 행 바로 아래에 이력 행이 펼쳐져 `일시 · 수정자 · 이전값 → 이후값`을 나열한다(REQ-15). 이력이 없으면 "변경 이력이 없습니다(초기값)."
- 가중치(신호×업종) 편집 UI는 이 화면에 없다.

## 9. 화면 흐름도

실선은 `frontend/src/router.tsx`에 있는 실제 라우트, 점선은 미구현(Phase 2/3) 화면이다.

```mermaid
flowchart LR
    Root["/ (역할별 첫 화면으로 이동)"] --> Login["로그인 /login"]
    Login -- "RM·지점장" --> Dashboard["오늘의 접촉 TOP 20 /dashboard"]
    Login -- "본부(마케팅)" --> Threshold["임계치 관리 /admin/thresholds"]
    Login -- "본부(준법)" --> Pending["안내 /pending"]
    Dashboard -- "행 클릭·상호명" --> Brief["브리프 상세 /brief/:id"]
    Brief -- "< 오늘의 접촉" --> Dashboard
    Dashboard -. "지점장, 미구현(Phase 2)" .-> Operations["운영 브리핑"]
    Dashboard -. "지점장, 미구현(Phase 3)" .-> Campaign["캠페인 상황판"]
    Threshold -. "미구현(Phase 2)" .-> Adoption["채택률 대시보드"]
    Pending -. "본부(준법), 미구현(Phase 3)" .-> Approval["승인 처리"]
```

- 미인증 상태로 보호 경로에 들어가면 `/login`으로, 권한 없는 역할이 다른 역할의 경로에 들어가면 자기 역할의 첫 화면으로 이동한다. 정의되지 않은 경로도 역할별 첫 화면으로 보낸다. 화면 가드는 UX용이며 최종 권한 검증은 API 서버가 한다.
- 이미 로그인한 사용자가 `/login`에 오면 역할별 첫 화면으로 이동한다. 세션이 만료되면 자동 로그아웃 후 `/login`에 만료 안내를 띄운다(§2).
- 기록(태깅)은 대시보드·브리프 상세 어디서든 페이지 이동 없이 저장된다. 브리프 상세에서 대시보드로는 상단 "< 오늘의 접촉" 링크나 사이드바 메뉴로 돌아간다.
