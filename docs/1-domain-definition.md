## 0. 문서 목적 및 전제

본 문서는 BranchSense의 요구사항(REQ), 유효성 제약(VAL), 엔티티, 도메인 규칙(RULE), 핵심 계산값 정의, 유스케이스(UC) 및 인수 기준을 정의한다. 비즈니스 목표·목표 사용자·범위 우선순위·기술 스택·일정·컴플라이언스는 `2-prd.md`에서 다룬다.

전제 조건:

- **개인 고객정보·거래정보 미사용**이 전 영역 최상위 원칙이다. 아래 모든 엔티티·규칙은 이 원칙을 위반하지 않는 범위에서만 설계한다.
- 순위 산정(스코어링·배제·임계치 판정)은 결정론적 규칙으로 수행하고, LLM은 확정된 결과를 문장으로 변환하는 역할에 한정한다(`2-prd.md` 5장 아키텍처 결정 참조).

### 용어

| 용어 | 정의 |
|---|---|
| 신호 (Signal) | 외부 데이터 소스에서 수집한 원시 변화값을 정규화한 레코드 |
| 이벤트 (Event) | 신호가 임계치를 초과해 실무 처리 대상으로 승격된 것 |
| 접촉 명부 (Contact List) | 지점별로 그날 접촉할 사업체 상위 20건 |
| 채택률 | 추천 중 '방문함'으로 태깅된 비율 |
| 태깅률 | 추천 중 태깅이 이루어진 비율 |
| 탐색 슬롯 | 표본이 적어 성과가 검증되지 않은 신호를 의도적으로 노출해 학습 데이터를 확보하는 자리 |

| REQ-04 | 분기 신호 감지 및 이벤트 승격 | 상가업소 점포 증감 등 분기 단위 소스를 갱신 시점에 이벤트로 승격한다 | Phase 2 |

## 2. 유효성 제약 (VAL)

| VAL | 대상 | 제약 |
|---|---|---|
| VAL-01 | 지점코드 | 필수, 전체 유일, 영문 대문자+숫자 조합 |
| VAL-02 | 담당 상권 반경 | 0.5km 이상 3.0km 이하의 수치 |
| VAL-03 | 지점 좌표 | 지오코딩 성공 필수. 실패 시 지점 정보 저장 불가 |
| VAL-04 | 사업자번호 | 10자리 숫자, 국세청 API 형식 규격 준수 |
| VAL-05 | 임계치 설정값 | 0 이상의 수치이며 대상 지표의 단위(%, 건, ℃ 등)와 일치해야 한다 |
| VAL-06 | 부적합 태깅 사유 | 이미 거래중 / 대상 아님 / 정보 오류 / 접촉 불가 중 정확히 1개 필수 선택 |
| VAL-07 | 캠페인 문자 초안 | 광고성 정보 표기·수신거부 문구 누락 시 지점장 검토 요청 자체가 불가 |
| VAL-08 | 계정 역할 | RM / 지점장 / 본부(마케팅) / 본부(준법) 중 하나. RM·지점장은 소속 지점 필수, 본부(마케팅)·본부(준법)는 소속 지점 없음. 본부 하위 역할 구분은 RULE-CAMPAIGN-01(준법 승인은 본부(준법)만 수행)의 전제 조건이다 |
| VAL-09 | 신호 기준일 | 모든 신호·이벤트는 소스별 기준일(as-of date)을 널 값 없이 보유해야 한다 |
| VAL-10 | 신호 가중치 | 0.2 이상 2.0 이하로 클리핑된 값만 저장 가능 |

## 3. 엔티티 정의

| 엔티티 | 설명 | 핵심 속성 |
|---|---|---|
| BRANCH | 영업점 | 지점코드, 지점명, 주소, 좌표, 담당상권(반경 또는 행정동 목록), 주력업종, 취급상품군, 외화취급여부, ATM대수 |
| USER | 시스템 계정 | 이름, 역할(RM/지점장/본부-마케팅/본부-준법), 소속 지점(본부 역할은 없음), 세션 정책(비활동 시 자동 로그아웃 시간·연장 가능 여부) |
| DATA_SOURCE_SNAPSHOT | 외부 소스 원본 응답의 날짜 파티션 적재본 | 소스명, 수집일시, 기준일, 원본 페이로드 |
| SIGNAL | 정규화된 신호 레코드 | 신호종류(사업자/상권/거시환경), 대상(지점 또는 사업체), 강도(0~1 정규화값), 기준일, 근거 스냅샷 참조 |
| EVENT | 임계치를 넘어 승격된 신호 | 원신호 참조, 지점, 승격사유, 발생일, 상태(활성/병합됨/절사됨) |
| BUSINESS | 접촉 대상 사업체(공개 데이터 기반) | 상호명, 업종, 위치, 영업상태(정상/휴업/폐업/영업정지), 최근 상태 갱신일 |
| RECOMMENDATION | 접촉 명부 1건 | 지점, 사업체, 점수, 순위, 선정 사유 신호 목록, 탐색슬롯 여부, 생성일 |
| BRIEF | 추천에 대한 생성 콘텐츠 | 추천 참조, 사유 1줄, 화법, 체크리스트, 출처 태그 목록 |
| TAG_FEEDBACK | 담당자의 1클릭 태깅 | 추천 참조, 태깅값(방문함/보류/부적합), 부적합 사유, 태깅 일시, 태깅 계정 |
| SIGNAL_WEIGHT | 신호×업종 단위 학습 가중치 | 신호종류, 업종, 가중치값, α, β, 최근 갱신일, 표본수 |
| OPERATION_FORECAST | 지점 운영 수요 예측 (Phase 2) | 지점, 예측종류(현금/ATM/외화), 예측구간, 근거신호, 기준일 |
| CAMPAIGN | 공익 이벤트 기반 캠페인 (Phase 3) | 트리거 이벤트, 상태(`DRAFT`=초안 / `MANAGER_REVIEW`=지점장 검토 완료·준법 승인 대기 / `APPROVED`=준법 승인 완료 / `HANDED_OFF`=발송 채널 이관 완료), 대상세그먼트(지점단위). 상태값 영문 코드는 `6-erd.md`의 `CAMPAIGN.status`와 동일하다 |
| CAMPAIGN_DRAFT | 캠페인 산출물 초안 | 캠페인 참조, 문구, 광고성표기 포함여부, 버전 |
| APPROVAL_LOG | 캠페인 승인 이력 | 캠페인 참조, 승인단계, 승인자 계정, 승인 일시 |
| THRESHOLD_CONFIG | 본부가 설정하는 신호별 임계치 | 신호종류, 임계치값, 단위, 최근 수정 계정·일시 |

## 4. 도메인 규칙 (RULE)

### 공통 (최상위)

| RULE | 내용 |
|---|---|
| RULE-SEC-01 | 개인 고객정보·거래정보는 어떤 엔티티·계산에도 입력되지 않는다. BUSINESS는 공개 데이터(사업자등록·인허가·상가정보)만으로 구성된다 |

### 지점 (BRANCH)

| RULE | 내용 |
|---|---|
| RULE-BRANCH-01 | 지점 정보 변경은 저장 즉시가 아니라 **다음 날 07:30 배치부터** 신호 범위에 반영된다 |
| RULE-BRANCH-02 | 동일 지점코드로 중복 등록할 수 없다. 기존 레코드 수정으로 처리한다 |

### 신호 감지 (SENSE)

| RULE | 내용 |
|---|---|
| RULE-SENSE-01 | 동일 대상·동일 신호종류가 쿨다운(기본 14일) 내 재발하면 새 이벤트를 만들지 않고 기존 이벤트에 병합한다 |
| RULE-SENSE-02 | 지점당 일일 이벤트는 상한(기본 8건)을 넘을 수 없다. 초과분은 점수 순으로 절사하고 "외 N건"으로만 표시한다 |
| RULE-SENSE-03 | 임계치(VAL-05, THRESHOLD_CONFIG) 미만인 변화는 EVENT로 승격하지 않는다. 단, SIGNAL 원장에는 저장한다 |
| RULE-SENSE-04 | 외부 소스 장애 시 전일 DATA_SOURCE_SNAPSHOT으로 대체하고, 해당 신호에 지연 배지(기준일 N일 전)를 표시한다 |
| RULE-SENSE-05 | 분기 갱신 소스(REQ-04)는 갱신일에만 이벤트 승격을 시도한다. 갱신일이 아닌 날은 일간 배치 대상에서 제외한다 |

### 접촉 명부 (TARGET)

| RULE | 내용 |
|---|---|
| RULE-TARGET-01 | 배제는 스코어링보다 먼저 수행한다. 배제 우선순위: 휴·폐업·영업정지 > 태깅 쿨다운(30일 내 접촉 이력) > 영구/한시 부적합 > 수신거부 |
| RULE-TARGET-02 | 점수는 `Score = (Σ wᵢ·sᵢ) × 근접도 × 규모적합도`로 계산한다. wᵢ는 SIGNAL_WEIGHT, sᵢ는 정규화된 신호 강도다 |
| RULE-TARGET-03 | 지점별 상위 20건을 RECOMMENDATION으로 확정하되, 그중 3건은 탐색 슬롯(RULE-LEARN-04의 표본 부족 조합에서 샘플링)으로 배정한다 |
| RULE-TARGET-04 | 탐색 슬롯 여부는 담당자 화면에는 노출하지 않되 내부 집계에서는 분리한다 |

### 브리프 (BRIEF)

| RULE | 내용 |
|---|---|
| RULE-BRIEF-01 | BRIEF의 모든 사실 문장은 출처 태그(`[소스명 · 기준일]`)를 가져야 한다 |
| RULE-BRIEF-02 | 도구 조회 결과에 근거가 없는 문장은 생성 단계에서 차단하고, 해당 항목은 사유만 표시한다 |
| RULE-BRIEF-03 | 확정 수익·원금 보장 등 금칙 표현은 화법·문구 생성에서 필터링한다 |

### 학습 루프 (LEARN)

| RULE | 내용 |
|---|---|
| RULE-LEARN-01 | 미태깅 추천은 채택률 분모에서 제외한다(태깅률은 별도 지표로 관리) |
| RULE-LEARN-02 | '보류' 태깅은 분자에서 제외하되 분모에는 포함한다 |
| RULE-LEARN-03 | 신호×업종 조합의 표본이 30건 미만이면 가중치를 갱신하지 않고 상위 계층 값을 상속한다 |
| RULE-LEARN-04 | 표본 부족 조합은 톰슨 샘플링으로 탐색 슬롯(RULE-TARGET-03) 대상으로 우선 선정될 수 있다 |
| RULE-LEARN-05 | 가중치 갱신은 주 1회 배치로 수행하며, 결과값은 VAL-10 범위로 클리핑한다 |

### 캠페인 (CAMPAIGN)

| RULE | 내용 |
|---|---|
| RULE-CAMPAIGN-01 | CAMPAIGN은 지점장 검토(`MANAGER_REVIEW` 진입)와 본부(준법) 역할 계정의 승인(`APPROVED` 진입, VAL-08)을 모두 거치지 않으면 발송 채널로 이관(`HANDED_OFF`)될 수 없다. 본부(마케팅) 계정은 이 승인 단계를 수행할 권한이 없다 |
| RULE-CAMPAIGN-02 | 모든 CAMPAIGN_DRAFT 문자 초안은 광고성 정보 표기와 수신거부 문구를 자동 포함한다(VAL-07) |
| RULE-CAMPAIGN-03 | 시스템은 실제 발송을 수행하지 않는다. 승인 완료 후 산출물은 기존 발송 채널로만 이관된다 |

## 5. 핵심 계산값 정의

### 5.1 이벤트 승격 판정

신호가 EVENT로 승격되는지는 아래 순서로 판정한다(우선순위 순).

1. 신호 강도가 THRESHOLD_CONFIG의 임계치를 초과하는가 (미달 시 SIGNAL로만 저장하고 종료)
2. 동일 대상·동일 신호종류의 활성 EVENT가 쿨다운(14일) 내에 존재하는가 (존재 시 병합, 신규 생성 안 함)
3. 지점의 당일 활성 EVENT 수가 상한(8건)에 도달했는가 (도달 시 점수 하위 항목부터 절사)
4. 위 세 조건을 통과하면 EVENT로 확정하고 발생일·근거 SIGNAL을 기록한다

### 5.2 채택률·태깅률·가중치 계산

```
태깅률 = 태깅된 추천 수 ÷ 노출된 추천 수
채택률 = 방문함 태깅 수 ÷ 태깅된 추천 수     (미태깅 제외, RULE-LEARN-01)

α, β  ← 지수감쇠 누적 (반감기 30일, 방문함=성공/부적합=실패로 베타분포 갱신)
p̂     = Beta(α, β)의 5% 분위수               (하위 신뢰구간, 표본 적은 신호의 과대평가 방지)
w     = clip( w₀ × p̂ / p̄ , 0.2 , 2.0 )        (p̄ = 전체 평균 채택률, VAL-10 범위로 클리핑)
```

표본수(n) < 30인 신호×업종 조합은 이 계산을 수행하지 않고 RULE-LEARN-03에 따라 상위 계층 가중치를 상속한다.

### UC-01. 지점 정보 등록

**사전조건**: 본부(마케팅) 또는 지점장 계정으로 로그인 상태
**기본흐름**: ① 지점코드·지점명·도로명주소 입력 → ② 주소 입력 시 좌표 자동 변환(VAL-03) → ③ 담당 상권(반경 또는 행정동)과 영업 성격 입력 → ④ 저장

**인수 기준**
- [ ] 주소 입력 후 3초 이내 좌표가 채워지고 지도에 담당 영역이 표시된다
- [ ] 필수 항목 누락 시 해당 필드 옆에 사유가 표시된다
- [ ] 저장된 지점 정보는 RULE-BRANCH-01에 따라 다음 날 배치부터 반영된다
- [ ] 동일 지점코드 중복 등록은 거부되고 기존 레코드 수정 화면으로 안내한다(RULE-BRANCH-02)

### UC-03. 사업자 상태 검증 배치 실행

**인수 기준**

- [ ] 상태가 '휴업/폐업/영업정지'로 확인된 BUSINESS는 즉시 배제 대상으로 표시된다(RULE-TARGET-01)
