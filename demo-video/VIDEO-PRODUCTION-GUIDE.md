# C-MAKER 시연 영상 제작 요청 가이드

이 문서는 Kiro에게 C-MAKER 시연 영상 제작을 반복 요청할 때 사용하는 표준 지침이다. URL, 데모 계정, 영상 길이, 강조 기능만 변경하면 기존 자동 촬영 방식을 재사용할 수 있다.

> **보안 원칙:** 실제 아이디와 비밀번호는 이 문서에 저장하지 않는다. 요청 메시지에서 일회성으로 제공하고, 자동화 스크립트에는 환경변수로만 전달한다. 영상·로그·보고서에도 비밀번호나 인증 토큰을 남기지 않는다.

## 1. Kiro에 보낼 요청 템플릿

아래 내용을 복사한 뒤 대괄호 부분만 수정한다.

```text
C-MAKER 시연 영상을 기존 demo-video 제작 방식으로 만들어줘.

[접속 환경]
- URL: [로그인 URL]
- 촬영 계정:
  - RM: [아이디]
  - 지점장: [아이디 또는 사용 안 함]
  - 본부 마케팅: [아이디 또는 사용 안 함]
- 비밀번호: [일회성 입력]

[영상 사양]
- 길이: [예: 3분]
- 해상도: 1920×1080
- 화면 자막: 포함
- 나레이션: Microsoft SunHiNeural 한국어 여성 음성
- 말하기 속도: -5%
- 결과 형식: H.264 MP4

[시연 흐름]
1. [예: RM 로그인]
2. [예: 오늘의 접촉 TOP 20 및 데이터 기준 확인]
3. [예: 신규 개업 신호 필터]
4. [예: 첫 번째 사업장 상담 브리프]
5. [예: 핵심·보조 근거와 출처]
6. [예: 규칙 기반 추천상품]
7. [예: AI 전화 화법]
8. [예: 방문함 태깅과 CRM 등록 파일]
9. [예: 본부 임계치 및 변경 이력]
10. [예: 엔딩]

[강조할 메시지]
- [예: 개인 고객정보를 사용하지 않음]
- [예: 대상과 순위는 규칙이 결정하고 AI는 화법만 작성]
- [예: 결과 기록과 CRM 등록 파일까지 현장 행동으로 연결]

[제작 요구사항]
- 촬영 전에 모든 클릭 대상과 데이터 상태를 사전 점검할 것
- 실제 값을 변경하는 관리자 기능은 조회만 할 것
- 태깅 등 촬영 중 생성한 데이터는 촬영 후 원복하고 다시 조회해 확인할 것
- 클립보드 권한 오류가 보이지 않도록 복사 버튼은 클릭하지 말고 강조만 할 것
- 음성과 자막이 각 장면에 맞는지 구간 길이를 검증할 것
- 완료 후 길이, 해상도, 코덱, 음량, 대표 프레임을 검증할 것
- 최종 MP4 경로와 검증 결과를 알려줄 것
```

## 2. 기본 제작 결과물

기본 작업 폴더는 `demo-video/`다.

```text
demo-video/
├─ content/
│  ├─ timeline.json            # 장면별 시작·종료 시각과 나레이션
│  ├─ narration.md             # 검토용 전체 나레이션 원고
│  └─ subtitles.srt            # 별도 제출용 자막
├─ scripts/
│  ├─ inspect.mjs              # 데모 사이트 사전 점검
│  ├─ preflight.mjs            # 녹화에 사용할 선택자 검증
│  ├─ record.mjs               # Playwright 자동 촬영
│  ├─ synthesize-neural.mjs    # 자연스러운 한국어 음성 생성
│  ├─ audio-report-neural.mjs  # 음성 구간 길이 검증
│  ├─ compose-neural.mjs       # 기존 영상에 신경망 음성 합성
│  └─ verify-natural.mjs       # 최종본 기술 검증
├─ artifacts/
│  ├─ raw/                     # 원본 WebM
│  ├─ audio-neural/            # 장면별 신경망 음성
│  └─ downloads/               # CRM 다운로드 시연 산출물
└─ output/
   ├─ C-MAKER-demo-3min-natural.mp4
   ├─ verification-natural-report.json
   └─ verification-frames/
```

새 영상을 만들 때는 기존 최종본을 덮어쓰지 않도록 다음과 같이 구분된 이름을 사용한다.

```text
C-MAKER-demo-[주제]-[길이]-[버전].mp4
예: C-MAKER-demo-RM-flow-3min-v2.mp4
```

## 3. 표준 제작 절차

### 3.1 환경과 데이터 점검

1. URL이 HTTP 200으로 응답하는지 확인한다.
2. 각 계정으로 로그인해 역할별 첫 화면을 확인한다.
3. 촬영일 추천 명부가 존재하는지 확인한다.
4. 추천 건수, 대표 신호, 첫 번째 사업장, 브리프 생성 상태를 기록한다.
5. 브라우저 콘솔 오류와 API 오류가 없는지 확인한다.
6. 개인정보, 실제 고객정보, 비밀번호, 토큰이 화면에 노출되지 않는지 확인한다.

데이터가 비어 있거나 지연·미수집 상태라면 바로 촬영하지 않는다. 먼저 사용자에게 알리고 데모 데이터를 준비하거나 시나리오를 조정한다.

### 3.2 시나리오와 타임라인 작성

기능을 나열하지 않고 하나의 업무 이야기로 구성한다.

```text
문제 제시 → 로그인 → 오늘의 명부 → 추천 근거 → AI 화법
→ 결과 기록 → CRM 연결 → 운영 통제 → 핵심 가치 제안
```

권장 장면 길이는 10~13초다. 각 장면은 `timeline.json`에 다음 형식으로 정의한다.

```json
{
  "id": 1,
  "start": 0,
  "end": 12,
  "scene": "title",
  "text": "장면에 맞는 나레이션 문장"
}
```

나레이션은 다음 기준으로 작성한다.

- 한 문장은 짧고 명확하게 쓴다.
- 화면에 보이는 내용과 같은 순서로 설명한다.
- 숫자는 TTS가 자연스럽게 읽도록 필요한 경우 한글로 쓴다.
- 전문용어를 연속으로 나열하지 않는다.
- 각 음성은 배정 구간보다 최소 0.25초 일찍 끝나야 한다.
- 구현되지 않은 기능이나 자동 학습·CRM 자동 연동을 과장하지 않는다.

### 3.3 사전 선택자 검증

전체 녹화를 시작하기 전에 `preflight.mjs`로 다음 요소를 빠르게 확인한다.

- 로그인 입력창과 버튼
- 대시보드 요약·데이터 기준·신호 버튼
- 신호 필터 칩
- 추천 사업장 링크
- 핵심 근거·보조 근거·추천상품
- 화법 복사 버튼
- 접촉 결과 버튼
- 방문함 탭과 CRM 메뉴
- 본부 임계치 제목과 변경 이력 버튼

텍스트와 숫자가 합쳐진 접근성 이름은 환경에 따라 달라질 수 있다. 가능한 경우 안정적인 CSS 영역이나 `hasText` 조건을 사용한다. 모든 선택자가 통과한 뒤에만 3분 전체 녹화를 시작한다.

### 3.4 브라우저 자동 촬영

기본 설정:

- Playwright + 설치된 Google Chrome
- 1920×1080
- 25fps
- 헤드리스 자동 촬영
- 화면 하단 고정 자막
- 주황색 가상 커서와 강조 테두리
- 오프닝·엔딩 타이틀 카드

촬영 주의사항:

- 로그인 비밀번호가 입력되는 장면은 짧게 보여주고 값은 화면에서 마스킹한다.
- 화면 이동 후에는 자막과 가상 커서를 다시 주입한다.
- `화법 복사`는 헤드리스 브라우저에서 클립보드 오류가 날 수 있으므로 클릭하지 않고 버튼만 강조한다.
- 임계치 저장, 수동 배치 실행 등 운영 데이터에 영향을 주는 기능은 실행하지 않는다.
- CRM 다운로드는 데모에 꼭 필요한 경우에만 수행한다.
- 방문함 태그를 만들었다면 추천 ID를 기록해 촬영 후 삭제한다.
- 태그 삭제 후 추천 목록을 다시 조회해 `UNTAGGED` 상태인지 확인한다.
- 엔딩 자막은 동적 주입에만 의존하지 않고 타이틀 HTML에 직접 포함한다.

### 3.5 자연스러운 나레이션 생성

Windows 기본 `Microsoft Heami Desktop` 음성은 사용하지 않는다. 기본 음성은 다음과 같다.

```text
패키지: node-edge-tts 1.2.11
음성: ko-KR-SunHiNeural
언어: ko-KR
속도: -5%
출력: 24kHz 96kbps mono MP3
```

외부 TTS 서비스에는 나레이션 문장만 전송한다. URL, 계정정보, 비밀번호, 토큰, 프로젝트 코드, 고객정보는 전송하지 않는다.

음성을 생성한 뒤 `audio-report-neural.mjs`로 모든 구간의 길이를 검사한다. 한 구간이라도 시간 안에 들어가지 않으면 다음 순서로 조정한다.

1. 불필요한 수식어를 제거한다.
2. 문장을 두 개의 짧은 문장으로 바꾼다.
3. 숫자 읽기 방식을 간결하게 바꾼다.
4. 최후 수단으로 해당 음성의 속도를 소폭 높인다.

### 3.6 합성

화면이 이미 검증됐다면 다시 인코딩하지 않고 영상 스트림을 그대로 복사한다.

- 기존 H.264 영상: `-c:v copy`
- 새 나레이션: 장면 시작 시점만큼 `adelay`
- 전체 음성: `amix`
- 최종 음성: AAC 48kHz, 192kbps
- 목표 길이: 타임라인의 정확한 길이
- 웹 재생 최적화: `+faststart`

기존 영상은 비교용으로 보존하고 자연스러운 음성 버전을 별도 파일로 생성한다.

## 5. 진행상황 보고 기준

긴 작업 중에는 사용자가 현재 상태를 알 수 있도록 다음 시점에 짧게 보고한다.

1. 환경과 데이터 점검 완료
2. 시나리오·나레이션 확정
3. 화면 녹화 시작
4. 화면 녹화 완료 및 데이터 원복
5. 음성 생성·합성 시작
6. 최종 검증 완료

보고할 때는 `완료된 작업 / 현재 작업 / 남은 작업 / 문제 발생 여부`를 함께 적는다. 단순히 “진행 중”이라고만 답하지 않는다.

## 6. 문제 발생 시 처리

### 선택자를 찾지 못하는 경우

- 전체 영상을 반복 촬영하기 전에 `preflight.mjs`를 수정해 빠르게 재검증한다.
- 숫자가 포함된 접근성 이름 대신 CSS 영역, 역할, `hasText` 조건을 사용한다.

### Playwright 녹화 FFmpeg가 없는 경우

```powershell
npx.cmd playwright install ffmpeg
```

브라우저 전체를 다시 설치하지 않고 Playwright 전용 FFmpeg 구성요소만 설치한다.

### 신경망 TTS 연결 오류

- 현재 사용하는 `node-edge-tts` 버전과 인터넷 연결을 확인한다.
- 구형 `edge-tts-node` 패키지는 현재 Edge 서버와 호환되지 않을 수 있으므로 대체용으로 사용하지 않는다.
- 음성 생성 실패 시 기존 자연음성 파일을 덮어쓰지 않는다.
- Windows 기본 TTS로 몰래 대체하지 말고 사용자에게 상태를 알린다.

### 나레이션이 시간보다 긴 경우

- 말하기 속도를 과도하게 높이지 않는다.
- 우선 문장을 짧고 구어체로 고친다.
- 마지막 장면은 엔딩 여운을 위해 최소 0.25초의 무음을 남긴다.

### 영상 중 오류 문구가 보이는 경우

- 대표 프레임으로 오류가 발생한 시점을 찾는다.
- 원인을 수정한 뒤 해당 장면만 가릴 수 있는지 검토한다.
- 오류가 제품 신뢰에 영향을 주면 전체 영상을 다시 녹화한다.
- 수정 후 같은 시점의 대표 프레임을 다시 확인한다.
